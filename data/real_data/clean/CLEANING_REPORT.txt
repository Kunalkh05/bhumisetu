6. REFINED CASE CLUSTERING (TASK 3)
--------------------------------------------------------------------------------
Previous naive clustering grouped notices solely by case_number, causing
different villages sharing serials (e.g., 4/A-65/2025-2026) to merge
inappropriately and create artificial date reversals.

New Hierarchical Key:
Cluster Key = District + Taluka + Mouza/Village + Case Number

Case Identifier Breakdown:
- Official Case Number Present: 163 cases (60.1%) (case_id_type = OFFICIAL_CASE_NUMBER)
- Derived Identifier Used      : 108 cases (39.9%) (case_id_type = DERIVED)
                                 (case_number is recorded as NULL, not fabricated)

Contradictory Event Orderings: Dropped from 6 down to EXACTLY 0.
